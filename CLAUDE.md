# Agent rules for 999-IN-1: The Bootleg Brawl

Read `README.md` first, then the last rows of `DECISIONS.md`. The plan is `999-IN-1 The Bootleg Brawl — Implementation Plan.md` in the owner's private docs repository, under `projects/bootleg-brawl/`. It is long, so search it for a topic instead of reading it whole. Plans, reviews and the playtest checklist live there too (D65). The owner's global Claude configuration names the repository. If you cannot find it, ask the owner. Do not add planning documents to this repository.

## Invariants

Tests, lint and the validator enforce these. Do not weaken a test or a rule to get past one.

1. The sim is deterministic. Code under `packages/engine/src/{sim,math,ecs,content,modules}` and `packages/mechanics/*/src` does not read clocks, `Math.random`, or float trig. Use the tick counter, `sim.rng` and `math/fixed.ts`. Positions and velocities are 16.16 fixed-point integers. ESLint blocks the common mistakes.
2. Everything the sim needs each tick is the array of `InputFrame`s. The renderer and audio read the sim and never write to it. Beat-synced gameplay derives beats from the tick and the track BPM, never from the audio clock.
3. A golden replay hash change means behavior changed. If the change is intended, re-record with `pnpm tools record-golden` and say why in the commit.
4. Mechanic modules add components, systems, hooks and schema fragments. They never patch core systems. A module gates its stage behavior on `sim.stage.rules.requires` or a character's `kit.requires`.
5. Adding a character, enemy, boss, stage or interlude is a content change. If it seems to need an engine change, add a module or a data field instead, and log the decision.
6. The IP rule: no character names, likenesses, catchphrases, dialogue, place names, logos, music or story beats from any franchise. Names are dictionary words, puns or misprints. `content/forbidden-terms.json` is the deny list. It is private and git-ignored (D61), and CI writes it from a secret. `pnpm tools validate` scans every text field and file name. A human reads every name and line an agent proposes.
7. Content files are the source of truth. `generated/` and `content/manifest.json` are build output. `content/rigs/*.rig.json` is generated by `pnpm tools gen-rigs` from `packages/tools/src/rig/poses.ts` and committed. Run it after you change the pose library.
8. Bundle budgets: `core` under 3 MB, each stage under 4 MB, each character under 1 MB. If a bundle goes over its budget, `pack` fails.
9. Every idle pose fits its rig frame box. The validator rejects overflow.

## The feedback loop

- `pnpm tools validate [path]` after every content edit. It prints one line per problem.
- `pnpm tools play <stage> [party]` for a quick headless playthrough.
- `pnpm tools metrics <stage> --players=2` after changing waves or segment lengths.
- `pnpm tools balance` after changing a character's numbers.
- `pnpm test` before a commit. It takes about ten seconds.

## What needs the user's approval

- Free inside the scope of a request: code, content, tests, `DECISIONS.md` rows and read-only cluster commands (`pnpm deploy:status`, `kubectl get`).
- Always ask first: every deploy (`pnpm run deploy`), every push, new cost, new dependencies and version bumps.
- Always ask before you change shared cluster resources: the Gateway `default/external-https`, the certificate map, or anything in another namespace.
- If a rollout fails, run `kubectl rollout undo deployment/bootleg -n bootleg-brawl` at once and then tell the user.

## Working habits

- Log every design choice or deviation from the plan as a row in `DECISIONS.md`.
- Do not use ports 5173 to 5177. They belong to the user. The game dev server uses 5180, the sandbox 5181, and Playwright's preview 4180.
- Stop every server you start and close every browser tab you open. The game plays music.
